# 0.6.3 · 两端资源准备、持久化与扫描优化

服务端与客户端同步更新至 **0.6.3**。协议继续使用主频道 v3 与私人频道 v1，现有配置无需覆盖。

- 全部 12 个固定权限节点默认关闭，普通玩家和 OP 均需通过权限插件显式授权；既有用户组、继承和通配符授权继续有效。服务器模型目录和伪装同时要求 `mact.use` 与 `mact.disguise`。
- 左侧所选模型的大预览复用当前模型的玩家姿态、镜头和持物流程，各模型仍保留独立参数、时钟与控制器。作者 `preview_animation` 仅用于右侧 YSM 小卡片，修复未使用模型的大预览误播卡片动画导致的倾斜与裁切。
- 玩家同步偏好立即在内存生效，同值跳过写盘，首次变更约 1 秒后合并后台保存；失败保留最新变更并重试。协调器跨后端重载复用，停服最多等待 250 ms，超时允许最后一批未保存。
- 本地完整模型源缓存只在查询和发布时短暂持锁，文件读取、解析、编码和数组复制在锁外；刷新世代使旧成功与错误结果失效。
- 世界模型、第一人称组件、载具／投射物及 GUI 预览使用有界纹理准备队列。PNG 解码、透明度与 atlas 拼接在后台，GPU 分批安装在客户端线程；无效资源不通过反复淘汰重做解码。
- 准备队列默认 1 worker、最多 8 个未完成请求、128 MiB 工作像素预留；每客户端 tick 最多安装一张纹理，约 1 ms 软门槛。首次准备通常以约 5 秒为目标，不含下载／解析，也不是硬耗时保证。
- 缓存校验后及时反馈 `cached`；完整安装、当前身份复核与 ready／ACK 完成前不切换本地接管。取消、断线、切换及资源重载释放过时任务与部分资源。
- 失败 hash 元数据限制为 256 条、60 秒 TTL，保留 30 秒重试冷却；成功安装清除对应失败记录。
- 同一观察者的资产授权集合按整次发现泵送／绑定校验批次合并重算；发现继续使用全服 128 候选／tick，实时授权检查和独立撤权保留。
- 私人观众采用最近 K 人堆，只排序入选者，保留距离、UUID 平局顺序、权限、可见性与关系准入顺序。动作、物理及既有模型更新频率不变。

本轮命令、源码身份、单元报告、失败尝试和最终构建随交付保存。实机显示由用户验收，未宣称 TPS、帧率、在线容量或长期内存实测通过。

## 实机验收清单

使用本次两端 JAR，分别覆盖缓存命中和首次下载；在每一步检查服务器／原版回退与当前模型显示。

1. 多人进入视野，核对人数上限、同距离观众、传送、换世界、隐藏与恢复可见性；准备期间不会提前隐藏原有显示。
2. 在下载、解析和分批纹理安装期间解除伪装、撤销观看权限或断线，确认迟到结果不能恢复旧模型；既有动作与物理保持原频率。
3. 查看第一人称手臂、载具及投射物组件，检查首次加载、透明纹理及随后动作更新。
4. 连续切换 GUI 模型、皮肤、作者配置与页面，关闭预览并反复刷新本地源，检查占位、最新模型及旧结果失效。
5. 在模型安装和私人分享准备期间重载资源包，检查有效模型分批恢复、ready／ACK 与缓存再次使用；无效纹理保留回退。
6. 连续更改同步偏好并重载后端，确认即时生效及最终保存；正常停服后重新启动核对持久化。慢磁盘超时可能丢失最后一批，日志应明确提示。

较长运行时结合 [资源状态](../SERVER_RESOURCE_PROTECTION.md) 和 [源码风险边界](../STATIC_REVIEW.md) 观察队列、预留、堆、原生纹理及主线程采样。单张 GPU 上传、ME 实例装配、表达式计算和客户端设置文件操作仍可能耗时。
