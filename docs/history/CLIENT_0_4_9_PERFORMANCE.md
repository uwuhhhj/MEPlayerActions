# 0.4.9 性能与同步维护

[文档索引](../README.md) · [安装与使用](../../README.md) · [客户端配置](../CLIENT_CONFIG.md) · [架构](../../ARCHITECTURE.md) · [协议](../CLIENT_PROTOCOL.md)

本次客户端与服务端均为 **0.4.9**，目标仍为 Minecraft／Paper 1.21.11、Java 21、Fabric。优化后台发现和重复同步的开销，动画输入、动作选择和物理仍按游戏 tick 推进。J 轮盘、三层显隐、服务器伪装优先级与私人分享的显式许可保持原有规则。

## 安装与旧配置

退出客户端，替换 `mods/` 中旧的 MEPlayerActions 客户端 JAR；停服后替换 `plugins/` 中旧的服务器插件 JAR，分别使用同版本安装 ZIP 中的 JAR。保留现有私人模型、客户端 JSON 和服务器配置，避免同时加载两个版本。首次安装可使用包内默认服务器配置；升级无需覆盖自己的整份 `config.yml`。

仅私人多人分享可以部署同一个服务器 JAR，无需 ModelEngine 或服务器资源包。服务器伪装仍需 ModelEngine R4.1.1 与对应资源包；GSit 为可选姿态后端。`privateSyncEnabled=false`、服务器私人模型开关和上传／观看权限仍默认关闭，优化不会自动开启分享。

服务器新增以下 `performance` 选项。旧配置缺字段时自动采用这些默认值；范围外的值会触发配置校验错误。

```yaml
performance:
  audience-refresh-ticks: 40
  validation-ticks: 20
  adoption-scan-ticks: 100
```

| 字段 | 默认与范围 | 用途 |
| --- | --- | --- |
| `audience-refresh-ticks` | 40，范围 20–100 tick | 较重的观看者发现，默认约 2 秒，错开不同实例的扫描 |
| `validation-ticks` | 20，范围 1–20 tick | 较重的有效性复查；轻量身份检查仍可每 tick 执行 |
| `adoption-scan-ticks` | 100，范围 20–100 tick | 原生服务器伪装的自动接管发现，默认约 5 秒，分批处理 |

秒数按名义 20 TPS 换算。调大后台发现间隔会延后新观看者或原生模型被发现的时间，不改变已有实例动画、物理和资产分片的 tick 推进。

服务器伪装的全部候选查询、位置比较与最近观众选择仅在重刷新执行，按 owner UUID 相位错开。已准入观众按有效性间隔复查在线、世界、可见性、距离、原 ME 过滤器和跟踪关系；每次更新仍检查过滤器一致性，客户端接管观众变化会立即标脏并调整配对。原生伪装发现每周期复制一次在线名单，再分批尝试接管；不逐 tick 重新扫描全部在线玩家。动作目录每会话创建一次，配置重载后随新控制器／会话重建。

## 增量状态与兼容

服务器模型频道仍为 v3，新能力使用 `incremental_state` 协商；只有双方 hello／ACK 均声明才启用。首次绑定保留完整状态，后续仅逻辑状态变化发送：动作层、策略、附件、缩放／显隐、世界、资产、饥饿值和动作目录等，普通位置变化默认不单独触发包。静态动作目录仅首次或改变时发送；同一 `owner/instance/hash/modelId` 的 `animations` 缺失表示保留目录，显式 `[]` 表示清空。未协商的新旧连接每 20 tick 发送完整 state 与目录，旧的缺失即清空语义保持。

增量连接仍使用 `heartbeat`，带最多 64 项一片的精确 `bindings:[{owner,instance,hash}]`。服务端发送前逐项复查当前 snapshot 的 instance／model／assetHash 与实际可见性，不为已失效关系续期。客户端只有已存在且完整身份相符的绑定才续期，不创建绑定、不为其他实例续租，也不因某片缺少一项就删除它。pending 绑定的 hash 可以为空；整片校验成功后才应用续期。显示接管仍单独完成资产、ready／ACK 与渲染租约校验，心跳不授予接管权限。

显式开启 `followServerTimeline` 的客户端另外声明 `server_timeline`，服务端保留每 2 tick 的位置／朝向状态；切换该选项会退还旧显示租约并重新握手，保留已知本人服务器伪装直到新快照确认。旧服务器拒绝新增能力时，客户端最多重试一次旧的两项能力握手；旧式 heartbeat 只更新连接时钟，绑定仍依赖旧式完整状态。旧客户端的 20 tick 完整状态间隔独立于 `validation-ticks` 配置。

逻辑变化只广播给已关联观众与 owner 本人，新观众由默认 40 tick 的后台发现纳入；单 owner 快照及本 tick 编码结果跨观众复用。资产 begin／chunk／end 每次发送仍检查精确绑定、当前快照和实际可见性。

完整快照恢复强制重发全部当前授权 state 与完整 `animations`，无需状态或目录变化，保留既有 binding／lease；预算延后的完整目录与后续最新状态合并，直到成功发送都不会被增量省略。

客户端收到经整片校验的增量心跳后，若发现未知 owner 或身份不匹配，会与本人绑定丢失共用最多每 2 秒一次的快照恢复请求。请求不指定模型或资产，仍由服务器判断可见资格并发送完整状态；合法分片未列出的绑定不会触发恢复。

## 出站预算与接管等待

正常限流返回 `DEFERRED`，保留已有绑定与接管，变化状态按 owner 合并为最新待发版本，后续维护重试；它不同于实际发送失败。unbind 等可延后的控制消息使用每会话最多 128 项的有界队列，每次维护最多尝试 4 项；正常预算不足继续等待，精确身份失效、等待 100 tick 到期、队列已满或实际发送失败时清理。旧 unbind 发送前若相同 instance 已重绑则跳过；成功发送新 state 也会取消相同 owner／instance 的旧解绑，避免撤销新绑定。会话轮转避免固定优先顺序。带宽额度、最大负载和租约边界保持有效，持续拥堵仍可能触发超时恢复。

ready 先构造 `render_ack` 并预留出站预算。首次预算不足只保留 pendingReady，不安装通道、不启用本地接管、不隐藏 ME；预算预留成功才尝试通道安装／启用。安装请求在主线程立即返回 pending，handler 安装交给 channel event loop，完成后回 Bukkit 主线程核对 owner／attachment 身份、当前连接、在线、观众和生命周期，再由后续 ready 维护重试。真正启用后才建立精确显示租约并直接发送已预留 ACK，不二次扣预算，`render_ack` 不进入延后控制队列；实际发送失败撤租并恢复 ME。

等待安装期间保持 ME，pending 最多 100 tick，临时 pending 不作为 `render_unavailable` 处罚。已确认租约的重复 ready 遇到限流继续保留；pending 到期不撤销仍在正常续期的既有租约。取消、换连接或关闭会撤销 token，并按 handler 身份异步移除，晚到完成不能恢复旧接管；实际安装失败进入失败恢复，不无限等待。

## 私人分享的后台维护

私人协议版本不变。服务器按发布者 UUID 缓存当前 generation 的最近观看者集合，默认最多 10 名其他观看者。新发布首次计算一次，其后默认每 40 tick 按 UUID 相位错开重算；已有关系每 20 tick 轻量检查。相关追踪／可见性事件立即撤销对应 offer 并使该发布者缓存失效，后续相位再发现观众。换 generation、移除发布、策略变更、停用或刷新间隔改变会清理对应缓存。

缓存只保存授权观众身份，不共享动画或物理运行状态。活跃资产队列每 tick 推进，各块发送前实时检查授权；配置／作者事件到包时直接转发给缓存中仍合法的观看者。私人服务禁用或没有发布时跳过重维护，不读取伪装状态供应器。缓存命中、连接存活或频率调整均不绕过权限、跟踪、服务器伪装优先级和租约。

## 服务端模型模板

服务器的 `YsmModelTemplates` 按蓝图名称缓存最多 64 个只读模板，包含不可变 clip 描述、已编译 Program 和 runtime Template，也缓存缺资源／普通模型的空结果。每会话的 clip、时间线、表达式上下文、事件进度、变量、运动与物理状态仍独立，不共享可变运行状态。服务器即使所有观众均由客户端接管，仍推进该模型的服务器动画与物理。

模板首次加载和被逐出后的重载仍在主线程读取 JAR、解析 JSON 和编译，缓存不能消除第一次加载成本。缓存随插件 classloader 生命周期释放，没有配置 reload 专用清空 API；被缓存的是固定 JAR 资源，不随 ME 蓝图重载而改变。观众身份与会话 owner 集合另用不可变集合缓存，减少重复枚举，不扩大授权范围。

本轮中央检查仅覆盖新增／受影响的定向单元、两端编译与包完整性；实际数量和最终结果记录在同版本 tests ZIP／build JSON。未启动 Minecraft 或服务器实机，没有 TPS、帧率或多人网络性能实测。减少重复扫描与序列化属于实现策略，不能视为实机性能提升数字。

交付包含两端 JAR、两端安装 ZIP、源码 ZIP、定向检查证据 ZIP 和构建 JSON。保留历史版本文件；私人 `.ysm`、用户模型源数据、私有复现夹具和本地配置秘密不进入交付。0.4.8 的真实文件离线导入、21 项单元结果及更早实机记录各自保留为历史，不作为本版重新验证的证明。
